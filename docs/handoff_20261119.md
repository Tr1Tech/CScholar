### Admin Bulk Import (added same day)

The CLI is no longer the only path. The admin UI now has **Bulk Import** (`/admin/import`) for staff, opened from **Theses / Capstone → Bulk Import** (a sub-flow of the collection, not a separate sidebar destination) or the dashboard's **Quick Management → Bulk Import** shortcut:

- Upload CSV + PDFs → **Check batch** preview (read-only) → **Import as drafts** → downloadable report. The template's sample row is rejected by validation, so it cannot be imported by accident.
- Runs as a background job (`import_jobs` table, `/api/import/*`); the screen polls progress. One batch at a time.
- Uses the same `app/services/importing.py` validation/import code as the CLI, so the two paths cannot drift.
- `Thesis Management` now has row checkboxes and **Approve selected / Publish selected** (`POST /api/theses/bulk-status`). The admin list now requests `per_page=100`, so records past the old 20-row ceiling are visible.
- Staff instructions: `docs/bulk_import_guide.md`.

### Faculty accounts + inline authors (2026-11-20)

- **Programs & Tags → Advisers** now edits adviser records, including the CSU email. The backend maps a faculty login to advised theses through `LOWER(advisers.email) = LOWER(user.email)`, so setting the real login email is what makes **My Theses**, **My Students**, **Analytics**, and the faculty dashboard show imported records. Advisers imported from a spreadsheet start with no email and are labelled **NO ACCOUNT**; that is deliberate — the importer does not invent addresses.
- Clearing the email unlinks the adviser again (`PUT /api/advisers/{id}` now accepts `email: null`).
- Both thesis forms now have **New author**: first/middle/last/email creates the student and selects them. `POST /api/authors` is open to admin **and faculty**, and de-duplicates by email, then by exact normalized name (a match returns 200 with `reused: true`). This unblocks next semester's new students, who previously required an admin to seed an author first.
- `GET /api/authors` and `GET /api/advisers` now include `middle_name` and `created_at` (additive).
