## 1. Decisions

1. **People pages are adviser-first.** One People screen with two tabs: Advisers
   (default), then Authors. Adviser profiles carry more data (multiple advisees
   across years); author profiles are mostly a directory at the current corpus
   size.
2. **Semantic search for faculty and admin: yes.** The endpoint is already
   `login_required`, so this is exposure and layout work, not new AI. Keep the
   published-only filter for every role.
3. **Recommendations are renamed "Related research."** The current rail returns
   the nearest neighbours of a source thesis; it is not personalized. Do not
   claim otherwise.
4. **No admin recommendation rail.** Admins need similarity/overlap detection on
   review, not a discovery feed.
5. **No Scholar-style profiles.** No bios, photos, citation counts, or h-index.
   The data does not exist and inventing it is worse than omitting it.
6. **No personalized recommendations yet.** `search_logs` and
   `recommendation_logs` exist but are empty; at 19 records there is no history
   to personalize from.

## 2. What already exists (checked in code)

- `models.list_theses(q=...)` matches title, abstract, keywords, and **author**
  first/last name. It does **not** match advisers.
- `GET /api/authors` and `GET /api/advisers` are public and return `email`.
  This is a live leak and a P0 fix.
- `POST /api/embeddings/search` is `login_required` and hard-filters
  `status='published'`. Any role can call it.
- `GET /api/theses/{id}/recommend` returns nearest neighbours of a thesis.
- `thesis_detail_screen.dart` says "Related research" on mobile and
  "Recommended Studies" on desktop; the copy diverges.
- `find_possible_duplicates` matches exact normalized title only. Embedding
  similarity would add real value on the admin review screen.
- Admin bulk import and `POST /api/theses/bulk-status` exist and are the
  intended publish path.

## 4. P1 — capstone

### Phase 1 — People layer (3-4 days)

```
GET /api/people?q=&type=author|adviser&page=&per_page=
GET /api/advisers/{id}   -> profile + published works, grouped by year
GET /api/authors/{id}    -> profile + published works + co-authors
```

Frontend: `/people` route, Advisers tab first, shared detail layout, reuse
`thesis_card.dart`. The repository people strip uses the same endpoint.

Rules:

- Anonymous and students see published records only; admin and faculty see all,
  plus a link into management.
- No emails outside admin. No bios, photos, or metrics.
- Label content as "works published under this name" until identity resolution
  exists. Dedupe is email-then-exact-name, so name collisions are possible.

### Phase 2 — Semantic search parity (1 day)

Expose the repository search in the faculty and admin shells. Keep
`status='published'` hard-coded in `semantic_search()`; do not add a role-aware
status filter that could leak drafts. Drafts stay in My Theses.

### Phase 3 — Related research (0.5 day)

Unify on "Related research", drop the "AI recommendation" copy, and surface the
rail on the faculty thesis detail.

### Phase 4 — Admin similarity check (1-1.5 days)

Add embedding-based near-duplicate detection on the review screen: "87% similar
to <existing published title>", using `recommend_for_thesis` with a threshold.
Warn, never block. This complements the exact-title-only guard.

### Phase 5 — Evaluation (1-2 days, required)

`docs/evaluation/queries.csv` with query, expected thesis ids, and role. A
script reports hit@1/3/5 and MRR for keyword versus semantic. Report the
small-corpus limitation openly.

### The real capstone blocker

Features are not the risk; 19 records are. Semantic search and people pages
demo well but cannot support a research claim at that size. Reaching 100-150
theses matters more than any feature above; 300 is the plan's finish line.

## 5. Risks

| Risk | Mitigation |
|---|---|
| Author name collisions merge two people | Label as name-based works; never merge across programs |
| Public `/api/authors` exposes student emails | Fix in P0 (§3.4) |
| Opening search to faculty leaks drafts | Keep published-only; drafts live in My Theses |
| "AI recommendations" claim is challenged | Rename to Related research; evaluate retrieval instead |
| Thin profiles at 19 records hurt the demo | Advisers first; only list people with at least one published work |
| Uncommitted work lost or mixed | Commit split in §3.1 before any feature work |
